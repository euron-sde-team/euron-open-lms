# Assessments: quizzes and assignments

A course item is a LECTURE, a QUIZ or an ASSIGNMENT. Quizzes are graded by the server
against a frozen snapshot of the questions; assignments are submitted in versions and
reviewed by a person against a rubric, optionally with an AI draft the person may ignore.
How completion then rolls up to the course is in
[progress-and-certificates.md](progress-and-certificates.md); the playbook for graders is
[guides/grading-and-moderation.md](../guides/grading-and-moderation.md).

![Quiz flow: start or resume, snapshot, autosave, submit before the deadline, grade from the snapshot, reveal per policy, first pass completes the item. Assignment flow: submit a version, queue, review with rubric, optional AI draft, decide](../assets/diagrams/assessments.svg)

## The question bank

Each course has its own bank (`questions`), edited in the course editor
([`apps/api/src/services/question.service.ts`](../../apps/api/src/services/question.service.ts)).
Every question is validated as a whole by `normaliseQuestion` in
[`apps/api/src/domain/authoring-rules.ts`](../../apps/api/src/domain/authoring-rules.ts):

| Kind | Rule |
| --- | --- |
| `SINGLE` | 2 to 8 options, exactly one correct |
| `MULTI` | 2 to 8 options, at least one correct |
| `TRUE_FALSE` | Exactly the options True and False, one correct |
| `SHORT_TEXT` | No options, 1 to 10 accepted answers, a `match_mode`: `EXACT`, `CASE_INSENSITIVE` (default) or `REGEX` (must compile, at most 200 characters) |

Option ids are generated by the server (`a`, `b`, ...) when the author sends none, so the
answer key never depends on ids a client invented. Points are 1 to 100. Tags drive RANDOM
draws. Deleting a question a quiz still uses archives it (`archived_at`): the quiz stops
drawing it and past attempts keep their snapshots.

The editor can ask the AI for draft questions from a lecture's text
(`POST /api/admin/courses/:id/ai/questions`): the drafts are returned, never saved, and an
author saves the ones they keep through the normal question routes, which validate them
again ([ADR 0017](adr/0017-ai-drafts-never-auto-applied.md)).

## Quizzes

Settings (`quizzes`): `selection` FIXED (an ordered list in `quiz_questions`) or RANDOM
(`draw_count` questions from the bank, optionally only those with any of `draw_tags`),
`pass_percent` (default 70), `time_limit_seconds` (30 s to 24 h, or none), `max_attempts`
(1 to 100, or unlimited), `shuffle_questions`, `shuffle_options` (default on), and the
reveal policy.

### Attempts and snapshots

[`apps/api/src/services/quiz.service.ts`](../../apps/api/src/services/quiz.service.ts),
[`apps/api/src/domain/quiz.ts`](../../apps/api/src/domain/quiz.ts):

- **Who.** Learners with access (`requireItemAccess`). Staff are refused with
  `409 STAFF_PREVIEW` (they preview quizzes in the editor), because an attempt would record
  progress for someone who is not learning. Quizzes are never free previews.
- **Start or resume.** `POST /api/assessments/quizzes/:itemId/attempts` returns the open
  attempt if there is one. A partial unique index allows only one `IN_PROGRESS` attempt per
  learner and quiz; two concurrent starts both try `number = max + 1`, one loses on the
  unique constraint and the retry returns the winner's attempt. An open attempt already past
  its deadline is first closed as EXPIRED.
- **Attempt policy.** `max_attempts` counts closed attempts (SUBMITTED and EXPIRED):
  `409 NO_ATTEMPTS_LEFT`. A quiz with no questions is `409 QUIZ_EMPTY`.
- **The snapshot.** `buildSnapshot` freezes the questions exactly as presented: which ones
  (a RANDOM draw), their order, each question's option order, points, and the answer key.
  Randomness comes from the OS CSPRNG (`crypto.randomInt`), so order is not predictable.
  The snapshot is stored on `quiz_attempts.snapshot`; later edits to the bank never change
  an attempt in progress or regrade history ([ADR 0016](adr/0016-quiz-attempt-snapshots.md)).
- **What the learner gets.** `presentAttempt` builds each question field by field: id,
  kind, rendered prompt, points, option ids and texts. No `correct` flags, no accepted
  answers, no explanations ([`apps/api/src/presenters/attempt.presenter.ts`](../../apps/api/src/presenters/attempt.presenter.ts)).
  The classroom's quiz card (`quizOverview`) shows counts, the pass mark, the time limit and
  past attempts, never questions.

### Autosave, timers and submit

- `PUT /api/assessments/attempts/:attemptId/answers` merges answers into the open attempt
  under a row lock. `cleanAnswers` keeps only answers to questions in the snapshot, in the
  shape their kind expects (option ids that exist, one id for single-answer kinds, text up
  to 500 characters).
- The **deadline is enforced by the server**, not the client timer: `deadline_at` is set
  at start; autosave past it is `409 ATTEMPT_OVERDUE`; a submit within a 5 s grace
  (`isOverdue`) is accepted with the answers it carries; after the grace the attempt closes
  as EXPIRED on the answers autosaved in time.
- `POST /api/assessments/attempts/:attemptId/submit` closes with a conditional update on
  `status = 'IN_PROGRESS'` under the row lock, so a double submit grades once; the repeat
  gets the graded attempt.

### Grading

`grade(snapshot, answers, passPercent)` reads only the snapshot:

- SINGLE and TRUE_FALSE: exactly one chosen, and it is the correct one.
- MULTI: the chosen set equals the correct set. All or nothing: partial credit would reward
  ticking every box.
- SHORT_TEXT: the answer, trimmed and with whitespace collapsed, matches an accepted answer
  per `match_mode`; REGEX patterns are anchored as `^(?:...)$` with the `iu` flags.
- An answer id that is not one of the question's options, a question not in the attempt or
  a duplicate entry earns nothing.
- `percent = floor(score * 100 / max)`; passed when `percent >= pass_percent`.

The first passing attempt completes the item in the same transaction (which may finish the
course and issue the certificate).

### Reveal policy

`mayReveal(policy, passed, attemptsLeft)` decides whether a closed attempt's result
includes the per-question breakdown (which questions were right, the correct options or
accepted answers, explanations):

| Policy | Reveal |
| --- | --- |
| `AFTER_SUBMIT` (default) | Always, once the attempt is closed |
| `AFTER_PASS` | When this attempt passed, or the learner has no attempts left |
| `NEVER` | Never |

When the key is not revealed, `result.questions` is empty, not just stripped of the
correct options: even "question 3 was wrong" gives away a TRUE_FALSE answer. Totals are
always shown, from the stored grade.

## Assignments

Settings (`assignments`): instructions (markdown), a rubric, `pass_points`, `due_days`
after enrolling (or none), `allow_late`, which kinds it accepts (text, files, an https
link) and `max_files` (0 to 20).

### Rubrics

A rubric is up to 20 criteria `{ id, title, description, maxPoints }` with `maxPoints` 1 to
1000; ids are kept when the author sends them and generated as `c1`, `c2`, ... otherwise
(`withCriterionIds`, `validRubric`). Scores are keyed by criterion id and clamped to each
criterion's maximum; unknown ids are dropped (`clampScores` in
[`apps/api/src/domain/rubric.ts`](../../apps/api/src/domain/rubric.ts)).

### Submissions and versions

[`apps/api/src/services/submission.service.ts`](../../apps/api/src/services/submission.service.ts):

- Learners with access only; staff get `409 STAFF_PREVIEW`.
- Only the kinds the assignment accepts (`400 KIND_NOT_ACCEPTED`), at most `max_files`
  files (`TOO_MANY_FILES`), links through `safeUrl` and https only (`URL_INVALID`), and not
  empty (`SUBMISSION_EMPTY`). Files are SUBMISSION uploads claimed by id
  ([ADR 0008](adr/0008-presigned-uploads-by-upload-id.md)).
- **Versions.** Every submission is a new row with `version = latest + 1` under
  `UNIQUE (item_id, user_id, version)`. A new version is allowed only after
  CHANGES_REQUESTED or REJECTED (`canSubmitNewVersion`): `409 SUBMISSION_PENDING` while
  one waits, `409 ALREADY_APPROVED` after approval. Of two concurrent submits one lands and
  the other is `SUBMISSION_PENDING`. Reviews attach to the version they judged.
- **Due dates** run from the enrollment's creation (`dueAt`). A late submission is flagged
  `is_late`, or refused with `409 PAST_DUE` when `allow_late` is off.

### Review

[`apps/api/src/services/grading.service.ts`](../../apps/api/src/services/grading.service.ts),
`/admin/grading` (area `grading`):

- **Who.** Instructors see the submissions of the courses they are on, in any course role
  (OWNER, EDITOR, GRADER); another course's submission is 404. ADMIN and SUPPORT see every
  course. Deciding needs a course staff role, or ADMIN.
- **The queue** is SUBMITTED versions, oldest first (`assignment_submissions_queue_idx`).
- **Decide** `{ decision: APPROVED | CHANGES_REQUESTED | REJECTED, scores, feedback? }` on
  a SUBMITTED version only, as a conditional update (`409 ALREADY_REVIEWED` otherwise).
  Scores are clamped; APPROVED needs `total >= pass_points` when the assignment has a pass
  mark (`422 BELOW_PASS_MARK`). CHANGES_REQUESTED and REJECTED are final for that version:
  the learner submits a new one.
- **APPROVED completes the item** for the learner in the same transaction.
- The learner is notified (`SUBMISSION_REVIEWED`) and the decision is audited
  (`grading.review`) with the scores and, when an AI draft existed, its model, its total,
  the difference from the human total and which criteria the human changed.

### AI suggestions

`POST /api/admin/grading/:submissionId/ai-suggestion` asks the AI provider for draft
scores, a reason per criterion and feedback, on a version still waiting for review.
`suggestGrade` ([`apps/api/src/integrations/ai/tasks.ts`](../../apps/api/src/integrations/ai/tasks.ts))
sends the instructions, the rubric and the submission text and link (files by name only;
their content is not sent), with the submission fenced as data and the system prompt
telling the model to ignore instructions inside it. The answer is clamped per criterion
and stored in `assignment_submissions.ai_suggestion`. It never changes the status or the
scores: the grader sees the draft next to the form and decides
([ADR 0017](adr/0017-ai-drafts-never-auto-applied.md)). Without a usable provider the route
is `503 AI_UNAVAILABLE`; a provider failure is `502 AI_FAILED`.
